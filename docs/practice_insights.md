# Practice insights and reflection

## Student flow

1. Open a course, confirm its topics in Study Plan, and start Practice. Each question has a confidence selector: Sure, Unsure or Guessed. Leaving it unselected means Not recorded.
2. Focus time is estimated for the question on screen; the practice page shows one question at a time, so the estimate follows Previous and Next without any button. Pause the timer during breaks. The interface explicitly describes this as selected-question wall time, capped at 120 seconds between interactions; it is not measured attention or a precise exam-time trace.
3. Before Submit answers, Review before submit lists unanswered, unsure and guessed questions. It never reveals correct answers or changes selections. Submission remains possible with unanswered questions.
4. After grading, Practice insights flags correct guesses, distinguishes recorded hint-assisted responses from responses with no in-app hints, totals tracked time by topic, and identifies the longest tracked question. Older sessions show missing measurements rather than fabricated zeroes.
5. Smart review list explains priority and can start a fresh session. Incorrect/unanswered responses, low confidence, confident mistakes, hints and unusually long tracked time increase priority. It is a heuristic, not a diagnosis. Only approved/legacy current question versions within confirmed scope can enter the session. Mixed-topic review is explicitly recorded as Mock Exam; single-topic review is Topic Practice.
6. Review answers (a button under the score) shows one question at a time with everything visible. On each incorrect or unanswered question, the section Reflect and explain your answer records a self-reported mistake reason: knowledge gap, careless error, time pressure, misreading, other or not sure. No reason is inferred automatically.
7. Explain your answer accepts up to 4,000 characters of the student's own reasoning. Save reflection works without AI. Check explanation with AI is a separate explicit action, available only with the existing Claude configuration. It sends the question, answer reference and explanation, validates bounded structured feedback, and never changes the score. Editing the explanation invalidates earlier AI feedback. Reflections happen after answer feedback and do not demonstrate independent mastery.
8. Try a different structure selects an approved question in the same topic with a different curated practice_structure tag, excluding all families in the source session. It does not merely reword the missed question or generate unreviewed material. The three demo banks have initial task labels; reviewers can edit labels through the versioned Study Plan workflow. Labels suggest contrasting tasks and are not a formal proof of transfer. If no eligible match exists, the UI explains how to approve more questions rather than promising a match.

Progress includes topic-time totals and a next-review list based on each family's latest response in the chosen practice mode. Learning DNA evidence tables show recorded confidence and hint counts. Practice history (a button on the Practice setup screen) lists unfinished and graded sessions; Open result reopens an existing result and its reflections without regrading.

## Persistence and compatibility

Tracking lives in bounded, validated `learning_state.practice_insights[session_id][question_id]` records in the existing course JSON. Confidence, hints shown and tracked time are captured on submission. Mistake reasons, own-word explanations and AI feedback are separate editable reflection metadata; answers and grades stay immutable. Records merge across distinct sessions/questions. Existing account save/restore handles the metadata without a database migration. Unsaved work stays in the login session, with an explicit warning when account saving fails.

For saved demos, Dashboard offers Add new demo questions. This is explicit and append-only: it preserves existing questions, topics, grades, confirmed scope, local history and review decisions, appending missing bank questions as pending review. It is idempotent and avoids duplicate stems. Existing question annotations are not silently rewritten; old untagged evidence stays untagged until a reviewer creates an annotated version and the learner answers it.

If the store sees the same question ID differing only in optional hints, cognitive dimension or structure labels, it retains the existing stored question snapshot. It still rejects changed stems, answer options, correct answers, explanations, topic links and version identity. Local historical snapshots receive the same protection. This accommodates fresh demo annotations after a failed restore without weakening grading integrity. Additionally, failed listing/restore blocks saves for the affected account/course until restore succeeds; the UI preserves local work and offers its existing retry flow.

No API keys or production database access were used during verification. AI output and persistence were tested with controlled fakes, with missing-key and service-failure paths checked. Live AI quality and real PostgreSQL integration remain outside these local checks.
